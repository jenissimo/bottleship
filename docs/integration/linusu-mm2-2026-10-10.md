## Deferred contracts and dependencies

The DirectMusic group is a substantial new subsystem, not a set of independent
MM2 menu fixes. Static review identified specific checks that must be resolved
before importing its runtime:

- `dmusic.ts::readStream` accepts nonnegative `IStream::Read` results without
  checking `pcbRead`. `S_FALSE` with a short read can therefore feed a partially
  filled RIFF buffer to a parser. Test short reads at the header and body boundaries.
- `guest-routine.ts::runGuestRoutine` reads the return address with an unguarded
  `DataView.getUint32(ctx.esp)` outside its generator exception handler. Validate
  the readable stack extent and callback targets, plus nested callbacks, allocation
  growth, failed dispatch and teardown of a suspended routine.
- `dmusic.ts::queryInterface` increments the object's reference count before the
  output-pointer write can fail. Test failure rollback, interface aliases,
  reference cycles and stream/loader reentrancy. Check reset/port/message disposal
  and timer cancellation across process exit and reload.
- The port/sink/performance dependency chain needs sustained audio and notification
  tests using synthetic or licensed music, followed by a legal game fixture. The
  fork uses Windows `gm.dls` if supplied; it documents silent default-collection
  instruments when that file is absent. No `gm.dls` was obtained or redistributed.

The MCIWnd group also needs separate testing. Its new AVI header scanner checks
`RIFF` but not the `AVI ` form and does not honor nested LIST extents. The MCIWnd
message subset, guest buffer permissions, window destruction/reload and intro
play/pause/resume/close behavior need checks before claiming that feature works.
The independent MCI timer correction included here does not imply MCIWnd support.

## Validation

- Full `bun run gate`: **5,413 passed, 0 failed**, 9 snapshots and 2,542,360
  assertions across 516 files. This includes typecheck and repository validators.
- `bun run build`: passed. Generated indexes produced no content changes.
- New LZX decoder extracted the real trial's 13 files. Every SHA-256 matched the
  preceding independent extraction using pinned `lzxd` 0.2.7, including the EXE,
  game archive and all licence/readme files. Synthetic tests cover verbatim,
  aligned, uncompressed, window wrap, repeat offsets, E8 translation and corrupt streams.
- Corrected regression on the user's Chrome on **Jen-AI**, using the repo CDP
  harness, `BS_TAB=linusu-integration`, a fresh `localhost:5205` origin and the
  unchanged previously authorized trial bundle: actual Cruise loading artwork
  visually inspected (**97% lit**); entered the city; acceleration scene motion
  **19.7**; **544 real Strided calls**; no draw stub, guest crash or GPU errors.
- Additional acceleration, left/right steering, brake and horn input sequence:
  **84 `bltfast:gpu:mixed:colorkey` operations**, 125 flip operations in the captured
  window, no guest faults/crash and no Strided stub. No frame-time speedup is claimed.
- Real output audio capture: 6 seconds, 48 kHz stereo, 288,000 frames, RMS 0.3367;
  no worklet underruns or starved blocks. The capture counted 17 frames at its
  saturation boundary. This is output evidence, not a subjective fidelity or
  original-Windows audio comparison.
- MCI resume test expires the pending video timer while paused, then checks one
  resumed delivery, no duplicate restart and no restart of a stopped device. It
  uses a synthetic decoder observer; it does not claim movie decoding was tested.

The first regression run's loading capture was rejected during visual inspection:
it still showed vehicle select after the worker had switched modes. The scenario
now waits for a new present after the mode change before capturing. The corrected
run, not the first run's 93% menu pixels, supports the loading-artwork result above.
Counting Strided calls proves handler coverage; it does not prove pixel parity for
every pedestrian. The trial's time and mode limits remain. The full game, DirectMusic,
MCIWnd intro and original-Windows visual/audio parity were not verified.

Local evidence is under `logs/linusu-integration/midtown-madness-2-demo/`
(`menu.png`, `vehicle.png`, `loading.png`, `race.png`, `report.json`) and the task's
`linusu-lzx-real-fixture.json`, `linusu-integration-gameplay.json`,
`linusu-integration-audio.wav`, `linusu-gate.log` and `linusu-build.log`.

## Reproducing the trial check

Load that lawfully obtained trial into a dedicated disposable test origin/profile
and handle its licence separately. Leave the main menu visible, then run:

```powershell
$env:BS_TAB = 'your-dedicated-test-tab'
$env:BS_DEV_URL = 'http://localhost:<your-isolated-port>/?game=dev'
$env:MM2_AT_MENU = '1'
bun tools/harness.ts run tools/harness/regression/midtown-madness-2-demo.harness.ts
```

The scenario selects Cruise explicitly, never deletes a container, never accepts
a licence and releases the accelerator, disables profiling and pauses on exit.
Visually inspect `loading.png` as well as the city view. Use the repository's full
reload workflow after worker changes; hot reload is insufficient.
