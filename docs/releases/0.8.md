BottleShip 0.8 adds LAN multiplayer, lays the groundwork for savestates and nearly
doubles the number of games we know to work. This release includes everything merged
since the 0.7 release on **October 8, 2026**, through **November 12**: more than
200 pull requests from the maintainer and nine outside contributors.

## What's new

- **Compatibility has grown from 53 to 85 entries.** Titles now working include
  **Half-Life 2, Command & Conquer: Red Alert 3, Deus Ex, Sid Meier's Pirates!, Unreal
  Tournament GOTY, Empire Earth, Grand Theft Auto 1 and 2, Colin McRae Rally 2.0 and
  RollerCoaster Tycoon Deluxe**. The full list of new titles is [below](#newly-compatible-games).
- **LAN multiplayer.** Browser tabs and computers can join one virtual LAN through a small
  relay server. Winsock games and DirectPlay 1–4 and 8 games find, host and join sessions
  as they would on a local network. [More below](#multiplayer).
- **The foundation for savestates.** Every major emulated module can now capture and
  restore its state. This is a developer feature in 0.8, not yet a button in the player.
  [More below](#savestates-the-foundation).
- **MIDI music.** A General MIDI software synthesizer now sits behind `midiOut`, the MCI
  sequencer and DirectMusic. It plays SoundFont 2/3 banks, and DirectMusic loads MIDI
  and WAVE files as segments.
- **Faster where it was slow.** Half-Life 2's 3D menu went from about 128 ms to 88 ms
  per frame on the maintainer's machine. Software-rendered GDI games, D3D9 vertex
  streams and file paths also got faster. Results depend on the game, browser and
  hardware.
- **The public demo library now has 48 entries.** New since 0.7:
  Grand Theft Auto and Grand Theft Auto 2 (the freeware Rockstar Classics releases), the Lord of the Rings: The Return of the King and Star Wars: Battle for Naboo demos, and the Midtown Madness 2 and Crimson Skies trials. [Try the library](https://bottleship.happydog.games/).

## Multiplayer

BottleShip can now connect several browser tabs or computers into one virtual LAN. Each
player connects to the same `bottleship-lan` relay server and picks the same room name.
The games then see each other as if they were on one local network. Open
**Settings → Network** to connect, then use the game's own LAN or TCP/IP menu.
**Copy invite link** shares the server and room.

What's in 0.8:

- **Winsock** (`wsock32`, `ws2_32`): TCP and UDP over IPv4 and IPv6, broadcast and IPv4
  multicast, and IPX datagrams. Each player has a stable virtual address on a shared
  subnet.
- **DirectPlay 1–4** (`dplayx`) and **DirectPlay 8** (`dpnet`) between BottleShip players:
  session enumeration, hosting and joining, players and groups, chat and messages, and
  DirectPlay lobbies. A game's launcher and lobby programs share one network identity.
- With a gateway that you configure on the server, BottleShip players can also join real
  Windows machines running DirectPlay 8 games.
- The relay is a small Rust program, `packages/lan-rust`, which runs with a single `cargo`
  command.

Games played this way include **Heroes of Might and Magic III, Worms Armageddon,
Quake II, Serious Sam, Re-Volt and Cossacks**. **GTA 1** was checked as a two-tab
DirectPlay match and **GTA 2** through its Manager with lobby chat. **Unreal Tournament
GOTY** was checked as a LAN listen server with a joining client. Empire Earth's LAN lobby
now accepts joining players, because default addresses share a subnet.

Limitations: there is **no public relay server yet**, so you need to run your own
([how](https://github.com/jenissimo/bottleship/blob/v0.8.0/docs/multiplayer.md)). Online
services and master servers of the original games don't work, and neither does joining
real Windows machines running DirectPlay 4 games. DirectPlay secure sessions, NAT
traversal and SPX aren't supported either. A game that loses its connection has to rejoin.

Multiplayer is new and has seen little play so far. Please try your games over the LAN
and report what works and what doesn't. Testing, bug reports and fixes are very welcome.

**The next minor release will finish multiplayer for players:** we plan to deploy our own
demo server, so you can play together without running anything yourself.

## Savestates: the foundation

Savestates will let you save a running game at any moment and resume it later, including
in games that only save at the end of a chapter or mission. Most of the work behind them
is merged in 0.8:

- A save format with deduplicated, compressed RAM chunks in browser storage, bound to the
  exact build and to the game's files.
- Saving at a safe point, and loading into a fresh worker before the game's first
  instruction.
- State capture for the core and all major modules. That covers the CPU, memory,
  scheduler, timers and kernel objects, windows and USER/GDI, DirectDraw, DirectSound,
  DirectInput, winmm, DirectMusic, Miles, Bink, Smacker, the C runtime, COM/OLE, common
  controls, ACM, Winsock and DirectPlay. Keys and mouse buttons held at save time are
  released after a load.
- A coverage check that refuses a save by name when a module still holds state it cannot
  save, so a save is never silently wrong.

In 0.8 savestates are available to developers through the automation harness behind a
flag. They are not exposed in the player yet. **Saving and loading for players comes in
the following releases.**

## Other changes

**Graphics.** Direct3D 9 takes vertex and index streams through its write ring without
extra copies, uses 16-byte-aligned buffers and has more fast paths. D3DX9 effects send
only the parameters that changed. Fixes include MultiplyTransform order, pre-transformed
draws in sub-viewports, lockable back buffers, the stencil enable state and released
texture lifetime. In DirectDraw and Direct3D 3–7, implicit primary presents are latched
to the display refresh. Strided draws, TransformVertices, D3D7 state blocks and depth-only
clears are fixed, and 8-bit display modes are offered at every size. D3D8 got
fixed-function lighting with pixel shaders and CPU-written back buffers. GDI text, DIB
sections, SetPixel and WinG work more faithfully. OpenGL fog uses eye-space distance,
and a new context starts with its window's viewport.

**Audio.** Sources slower than the output are resampled with a band-limited filter, which
removes grain from low-rate music. DirectSound cursors, wrapped Unlock writes, primary
buffers per device, status flags and SetFrequency follow Windows more closely. Miles
streams resume at their seek position and run their timers on the right thread. OpenAL
streams start at their first buffer. Pausing the game silences audio, and a pause is no
longer undone by an automatic resume.

**Input and windows.** Key presses type the character of your keyboard layout. The right
Ctrl, Alt and Shift keys reach the game as their own keys. A pointer the game keeps
warping back is no longer drawn. USER32 has more window-state, message and DDE behavior,
plus accelerators, cursors and icons from resources, GetInputState and character
classification. Modal dialogs keep their timers and run their own message pump.

**Processes and the runtime.** CreateProcess carries the command line, STARTUPINFO and
inherited handles to the child, and WinExec is built on it. Each process has one C
runtime. kernel32 adds fibers, atom tables, profile sections and more VirtualAlloc
cases. JIT-compiled code that writes into its own code page now stops before the store
and lets the interpreter replay it.

**Importing and bundles.** New installer support covers ZIP self-extractors, multi-volume
InstallShield 5 and Unreal `.uz` files, plus more Inno, RAR4 and MSI variants.
`make-wgb --sdb` applies a game's own compatibility shims, and `--copy` adds files that an
installer script creates. WGB members can now be block-compressed and still stream by
range. Savestates don't depend on how a bundle is packed. The setup wizard adds a
*Language for non-Unicode programs* setting. New imports default to 1024 × 768,
32-bit color and 128 MB of RAM.

**Mobile.** On iOS and iPadOS 27, the JIT runs in a mode without tail calls by default.
This avoids a WebKit failure seen in Hitman and Max Payne. Guest memory is zeroed lazily
so larger games fit in Safari. Touch controls let you choose WASD, arrows or the numpad
for movement and use per-orientation phone layouts.

**Tools.** The harness can drive iPhone Safari over a remote bridge. It can also inspect
DirectPlay rosters and DirectDraw textures and measure memory use. A smoke checklist
guides manual regression passes.

## What's next

1. **Multiplayer for everyone.** The next minor release will finish multiplayer and deploy
   our demo server, so players won't need their own relay.
2. **Savestates for players.** The foundation is in 0.8. Upcoming releases will turn it
   into saving and loading at any moment from the player.
3. **A faster JIT.** In [#105](https://github.com/jenissimo/bottleship/issues/105) we
   compared our x86→Wasm output with Emscripten builds of the same C++ code. On small
   kernels taken from Need for Speed: Underground, our code is about 10–16× slower (more
   for x87 math). The emitter isn't the main cost. The cost comes from the x86 guarantees
   our generated code keeps: a memory check on every access, CPU state written back at
   every exit, exact flags, and short blocks with frequent jumps between modules. Next we
   want to profile Direct3D 9 games such as Half-Life 2 and look at relaxations that keep
   those guarantees where a game can observe them. Candidates include loop-scoped memory
   checks, inline SSE through Wasm SIMD and passing registers between compiled blocks.
   Each change stays off until it shows a gain in a game. We can't promise a speedup yet.
   The issue lists the measurements, what we've already tried and good first tasks.
   Contributions are welcome.
