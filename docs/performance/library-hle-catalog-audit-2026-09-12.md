# Каталог библиотечного кода: проверка постановки и имеющихся данных

**Уточнение 13.09:** [сохранённые EIP пересечены с актуальными libid-индексами](nfs-frame-work-diagnosis-2026-09-13.md).
Проверка выявила смещение таймерного EIP-сэмплера к границам исполнения Wasm;
его счётчики нельзя использовать как доли времени для ранжирования HLE.

**Дополнение:** после указания пользователем `G:/WGB` образ NFSU2 извлечён и исследован.
[RE диспетчера D3DX Effect и нового контракта](nfsu2-eagl-re-2026-09-12.md).
Указанное ниже отсутствие `speed2.exe` относится к первоначально проверенным локальным
корпусам; этот пробел теперь закрыт. Пробел точной временной атрибуции остаётся.

2026-09-12. Только offline-анализ: прочитаны сохранённые PE, Ghidra projects, AOT и
отчёты трасс. Игры не запускались, runtime/инструменты проекта не изменялись. Сохранены
аналитические JSON ниже. Новая Ghidra auto-analysis не запускалась; проекты открывались
через `DefaultProjectData(locator, false, false)` и `getReadOnlyDomainObject`.

## Решение

Каталог библиотечных функций — полезный следующий шаг generic HLE. Однако в дереве
уже есть существенная часть опознания. Первым следует связать существующие результаты
с горячими регионами целевых игр, затем расширять распознавание по неразрешённому
горячему коду. Строить полный каталог всех версий middleware до этой проверки не нужно.

Полный рейтинг «доля кадра × число игр» по имеющимся данным сейчас недоказуем. Ниже
даны реальные результаты идентификации и конкретные отсутствующие связи. Отсутствие
числа означает неизвестное значение, а не ноль.

## Что удалось получить без новых замеров

### 1. Сохранённый Function ID уже даёт библиотечный каталог

В установленной Ghidra есть `vsOlder_x86.fidbf` и другие VS Function ID базы.
`C:/ghidra/Ghidra/Features/FunctionID/data/building_fid.txt` перечисляет исходные
семейства Visual Studio 1998, 2003, 2005 и более поздние. Это готовая основа для CRT;
FLIRT не является единственным способом опознания. Сам FLIRT сопоставляет функции
по библиотечным сигнатурам, но не гарантирует распознавание всего чужого кода:
[описание Hex-Rays](https://docs.hex-rays.com/user-guide/signatures/flirt/ida-f.l.i.r.t.-technology-in-depth).

Прочитаны 59 сохранённых Ghidra programs, 58 различных полных SHA-256. Выгружены
13 207 существующих `Analysis / Library Function` bookmarks. Среди них — 5670 различных
текущих имён функций с пометкой `Single Match`. Это не число семантически уникальных
функций, не число игр и не число пригодных HLE-кандидатов: варианты ABI, namespace,
версии и совпадения требуют дальнейшей нормализации.

[Каталог и исходные свидетельства](../../logs/library-catalog-20260912/cached-fid-catalog.json)
содержат SHA образа, исходный путь, image base, имя/границы функции, source символа,
текст bookmark и признак Single Match. Неоднозначные пометки сохранены отдельно через
этот признак. Имя функции без такого свидетельства не включалось в Single Match counts.

Для NFSU `Speed.exe`, SHA-256
`c0fad450912952f53809a54690d235aa8b4e25b9f46650693c7cbee1b4c074b7`:
10 054 определённых Ghidra функций, 248 библиотечных bookmarks, 236 Single Match.
236/10054 — НЕ доля CPU-time и НЕ полный охват библиотечного кода. Например, EAGL
остаётся `FUN_*` в этом проекте, хотя существующий дескриптор опознаёт его отдельно.

### 2. Три EAGL-сигнатуры проверены на локальном PE-корпусе

В `tmp/` и `.tmp/` проверены executable sections всех найденных x86 `.exe`/`.dll`:
69 файлов, 57 различных SHA-256. Точные совпадения текущих сигнатур:

| Функция дескриптора | VA в NFSU | Длина фактического pattern | Подтверждённые уникальные образы |
|---|---|---:|---:|
| shader_const_convert | 0x005cbd17 | 60 bytes | 1 |
| apply_reg_int | 0x005c85c1 | 61 bytes | 1 |
| state_token_dispatch | 0x005c97cb | 79 bytes | 1 |

Обе копии `tmp/nfsu/Speed.exe` и `tmp/re/Speed.exe` имеют один полный SHA; это один
результат, а не две игры. Других exact matches в этом корпусе нет. Это НЕ устанавливает
отсутствие других версий EAGL. Комментарий converter говорит о 56 bytes, но фактический
Uint8Array содержит 60 — для анализа использован массив, а не комментарий.

[Полный scan с паттернами и хэшами](../../logs/library-catalog-20260912/existing-eagl-scan.json).
Scan подтверждает байтовое опознание; доказательства ABI/effects остаются в существующем
дескрипторе и тестах. Три функции уже имеют HLE-пути — их исторический выигрыш нельзя
снова записать в резерв. Дескриптор отдельно документирует холодный `apply_reg_int`.

## Предварительная таблица кандидатов

Это **таблица установленных сущностей, не рейтинг FPS**. Охват ниже считается по
уникальным образам с существующей Single Match пометкой в RE-корпусе; это нижняя
оценка обнаруженного присутствия, не охват списка совместимости. Состав библиотек
в разных образах может отличаться. Стоимость — инженерная оценка формы работ,
не полученная из trace оценка трудозатрат.

| Функция/семейство | Библиотека / VA NFSU | Доля CPU-time NFSU | Образы с Single Match | Оценка реализации и ценности |
|---|---|---|---:|---|
| __ftol | CRT, 0x00672fc8 | неизвестна | 13 | Тело небольшое, но x87/ABI требуют точного контракта; отдельная граница HLE может съесть пользу. Предпочтителен горячий цикл вызывающего кода; converter EAGL уже устраняет часть таких вызовов |
| _memcpy | CRT, 0x00678d30 | неизвестна | 3 | Средняя: диапазоны, faults, точное продолжение, размерная модель overhead. Существующие bulk kernels сокращают объём реализации, но не доказывают игровой эффект |
| _memset | CRT, 0x0067ef80 | неизвестна | 15 | Аналогично; сначала распределение длин и current served path |
| _strlen | CRT, 0x00674c30 | неизвестна | 14 | Средняя: scan до границы страницы, precise fault, короткие строки и стоимость перехода |
| _malloc | CRT, 0x0067121a | неизвестна | 13 | Высокая для замены allocator: ownership, CRT heap metadata, смешанное обслуживание, realloc/free и callbacks; имя malloc не задаёт единый ABI состояния |
| _free | CRT, 0x00671102 | неизвестна | 6 | Рассматривать совместно с владельцем allocator, а не как независимый быстрый leaf |
| EAGL converter / token dispatch | EAGL, адреса выше | текущий остаток по функциям неизвестен | 1 exact PE build, другой метод | В NFSU уже реализовано; для NFSU2 нужны RE фактической версии и доказательство ABI. Средняя/высокая стоимость |

Пример проблемы знаменателя: 13 образов с `__ftol` включают `quake2.exe`, `ref_gl.dll`
и `ref_soft.dll`. Это одна игра с несколькими модулями/режимами. Кроме того, корпус
включает Far Cry, поздние игры, утилиты и модификации; он не равен набору 2000–2003.
Простое перечисление имён без фильтра Single Match даёт большие числа — например,
`_memcpy` встречается по имени в семи образах, но только три имеют нужную пометку.

## Чего не хватает для столбца «доля времени»

1. **Точная связь runtime profile → guest region.** Имена `g<VA>@t<slot>` обозначают
   вход сгенерированной Wasm-функции, способной содержать много guest blocks и функций.
   Например, горячий NFSU entry `0x0040d001` находится внутри Ghidra-функции
   `0x0040cd40–0x0040d080`, а не на её входе. Адресное попадание устанавливает владельца
   entry, но не владельцев всех сэмплов сгенерированного модуля.
2. **Соответствующие trace публикации и guest instruction map.** В сохранённом
   `logs/nfsu-jit-joint-rewarm-20260905/publications.json` прямо указано
   `guestInstructionMap: { status: "unavailable" }`. Это другой capture; его bytes или
   table slots нельзя автоматически привязать к текущему trace. В актуальных detail
   JSON есть aggregates и hotblocks, но нет карты Wasm instruction ranges → guest
   function ranges с проверенной generation/идентичностью bytes.
3. **Профиль с нужной разрешающей способностью.** Даже наличие карты emitter не
   гарантирует, что сохранённый Chrome CPUProfile содержит точный PC каждого сэмпла
   внутри Wasm-функции. Нужно проверить источник offset, либо использовать отдельно
   измеренный регион/контекстные стеки и оставлять смешанные участки неатрибутированными.
4. **Fingerprint фактического guest image.** SHA извлечённого PE известен; имеющиеся
   встроенные hotblocks называют `speed.exe`/`speed2.exe`, но не доказывают тождество
   образа и всех runtime patches конкретному RE-проекту. Нужны SHA/build/base и учёт
   relocation, IAT, HLE/SMC patches. Старый кэш не подменяет эту связь.

Сохранённый AOT действительно доступен:
`logs/source-pair-PIWSnO/game-capture/0/aot-original/index.json`, 88 units, 194 page
records. Unit содержит `entryPage, tableIndex, pages, file, bytes`; страница —
`physPage, stateFlags, entries, sha`. Это информация о захваченной компиляции и
публикации. Она не доказывает исполнение каждой ветви, не содержит веса CPU-time
по исходным функциям и не является полным списком исполнявшегося кода игры.

Встроенные hot EIP samples также нельзя механически трактовать как CPU-time:
использованный путь наблюдения может чаще видеть yield/парковочные границы.
Текущие 31%/41% JIT self-time NFSU/NFSU2 — широкие категории, не доли собственного
кода движка. Отчёты трасс пригодны для поиска приоритетных модулей и регионов;
точное вычитание библиотечных процентов пока невозможно.

## Чего не хватает для столбца «число игр»

`docs/compatibility.md` содержит 47 игровых строк, но не манифесты образов. NFSU2 в
этой таблице отсутствует. У каждой игры нет единой проверенной связи с build/version,
списком guest-loaded модулей, их SHA и текущей политикой HLE/native routing.
Часть RE-кэша содержит только отдельный исследованный DLL, не всё приложение.

`public/games-catalog.json` содержит 13 записей; ни один из указанных там WGB targets
не лежит сейчас по своему `public/...` пути. Это не доказывает отсутствие бандлов
в OPFS или внешнем хранилище. Распаковки и сохранённые Ghidra-образы уже позволяют
начать частичный census, но выдавать его за проверку всех 47 игр нельзя.

Нужны отдельные поля: проверенные игры, проверенные сборки, модули, версии функций,
непроверенные игры, присутствие на диске, реальное выполнение и выигрыш. Непросканированный
образ имеет статус unknown; отсутствие exact pattern — no exact match, не no library.

## Поправки к исходной задаче

- Добавить к FLIRT готовые Ghidra Function ID и существующие RE/HLE descriptors;
  сохранять источник опознания и неоднозначность. Семантически одинаковые функции
  разных компиляторов кластеризовать отдельно от доказанной ABI-совместимости.
- Разделить статически встроенный guest code, реальные guest DLL, импорты,
  BottleShip HLE и generated stubs. Bink и динамические D3DX уже имеют HLE-модули;
  наличие DLL/import не доказывает, что его native тело исполняется.
- Fixed-function T&L D3D8/9 не считать автоматически библиотечным x86-кодом образа:
  в BottleShip есть собственный HLE/backend FFP. Guest-side vertex processing игры,
  статический D3DX, native DLL и backend shader work требуют разной атрибуции.
- **Неопознанный код ≠ собственный код движка.** Нужны категории confirmed library,
  confirmed engine/application, runtime/HLE/generated и unresolved. Shared engine/EAGL
  тоже может обобщаться на семейство игр; происхождение и применимость HLE — разные оси.
- Сначала ранжировать по устранимому текущему CPU-time на NFSU/NFSU2. Статический
  охват служит отдельным сигналом переносимости. `p_NFSU × N_games` не оценивает пользу
  других игр: часто встречающийся код может быть холодным во всех их игровых сценах.

При достаточных данных полезная оценка для одного кандидата:

`score = Σ_game weight_game × net_saved_time_fraction_game / engineering_cost`.

`net_saved_time` включает guards, fallback, переходы и оставшуюся работу. Confidence
идентификации/ABI и версия функции — отдельные критерии допуска. Пока нет dynamic
данных других игр, не заполнять их доли по NFSU; показывать static coverage рядом.
Перекрывающиеся кандидаты, например `__ftol` и вызывающий EAGL converter, не суммировать.

## Следующее полезное действие

Первые кандидаты для проверки CPU-бюджета — горячие EAGL/CRT regions NFSU/NFSU2,
уже обнаруженные current traces + существующим RE. Полная таблица с экономией
потребует точной атрибуции регионов; эту недостающую связь надо закрыть раньше,
чем тратить недели на новые библиотечные handlers. Для NFSU2 по-прежнему нужен образ
фактической версии или его сохранённый RE/memory export: в проверенных локальных
PE/RE-корпусах `speed2.exe` не найден.

Снимать HLE первым по одним найденным именам пока не обосновано. Статический каталог
оказался существенно богаче исходной постановки; недостающая инфраструктура — его
связь с выполнением, сборками и целевым выигрышем. Доля «собственного кода движка»
в NFSU по этим данным **не установлена**.
