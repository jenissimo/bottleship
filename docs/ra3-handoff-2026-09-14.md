# RA3 «чёрный мир» — handoff, 2026-09-14

## Статус одной строкой

Чёрный мир **починен**: сцена рендерится (база, техника, рельеф, дороги), `sceneProbe`
brightness 8.01 → 53, motion 0 → 0.44. Остались два визуальных дефекта и две несвязанные
задачи из исходной тройки. Ничего не закоммичено.

## Что было и как выяснилось

Симптом: в миссии чёрный мир при корректном HUD и живой миникарте.

Ключевой поворот — **дампы самих таргетов**, а не их статистики. `rtGallery` показывал
«uniform», из чего легко сделать вывод про свет или композит (я его и сделал, дважды, и оба
раза ошибся). Дамп `dumpSurface` показал другое: depth prepass с 260 draw'ами пуст, shadow map
с 405 draw'ами чёрный, и в обоих — **одинаковый красный клинышек в левом нижнем углу**.
Одинаковый артефакт в двух независимых проходах с разными матрицами означал не освещение, а
трансформ.

`captureFrame` подтвердил: **693 из 1321 draw'а шли с `vertexShader: 0` и единичной MVP**, а
вершины у них модельные. То есть геометрия уходила в clip space как есть и схлопывалась в угол.
Дальше цепочка раскрутилась до d3dx-эффектов.

## Цифры

- отказы создания шейдеров: **40 → 0** (62 vertex + 67 pixel создаются)
- отказы селекторов FXLC: **было 2 вида → 0**
- `apiFailures`: остался только `CheckDeviceMultiSampleType → NOTAVAILABLE` ×8 — честный ответ, не баг
- `d3dxTextures`: `cube:ok: 2`

## Новые инструменты (durable, не выбрасывать)

- **`tools/shader-offline.ts`** — гоняет наш `compileVertexShader`/`compilePixelShader` по
  выгруженным блобам **вне эмулятора**. Именно он развёл «наш парсер плохой» и «мы подсунули не
  те байты»: 1732 блоба, все 1732 компилируются. Флаг `--disasm` отдаёт упавшие в `d3dx-oracle`.
- **харнесс-верб `effectShaderBlobs`** — все шейдерные объекты пассов в base64 с эффектом-владельцем.
- **харнесс-верб `effectSelectors`** — FXLC-выражения индексов шейдерных массивов.
- **`d3dx-oracle.ts ctab-bin <file>`** — константная таблица готового блоба.
  ⚠️ На preshader **не работает**: версионный токен `0x46580200` («FX 2.0»), настоящий
  `D3DXGetShaderConstantTable` возвращает `S_OK` с пустой таблицей. Проверено, не тратить время.
- Диагностика: отказ создания шейдера теперь печатает размер, version-токен, первые 8 байт и
  текст объекта; селектор различает «не вычислилось» и «вне диапазона» с настоящей причиной.

## Что осталось

### 1. Белая заливка вместо обводки при наведении (ПРИОРИТЕТ)
Гипотеза пользователя, очень правдоподобная: так рисуется обводка выделения. Заливка силуэта
вместо контура — признак того, что маску нарисовали, а шаг выделения краёв не отработал.
**Не измерено.** Мешает то, что ИИ доигрывает скирмиш за ~4 минуты и сессия уезжает на экран
статистики — снимать надо сразу после входа в миссию.

Как мерить: `tools/probes/ra3v-hover.harness.ts` (готов, `HOVER=x,y`) — навести на юнит,
`captureFrame`, смотреть состояния стенсиля, blend, `colorWrite` у этих draw'ов.
**Оракул здесь d3dx9-шный НЕ подходит** — это вопрос про состояния устройства. Правильный:
`bun run gate:d3d9-capture` (дифференциальный захват против настоящего D3D9) и Rust-оракул на
`D3DDEVTYPE_REF`. Но применять только после того, как известна конкретная пара состояний —
иначе повторится ошибка этой сессии, когда REF-оракул собрали на нетрансформированном FVF и он
«подтвердил» неверный вывод.

### 2. Синеватый пересвет сцены
Не исследовано. Возможная зацепка из `effectConstants`: `ColorAmbient`, `ColorDiffuse`,
`ColorSpecular`, `ColorEmissive`, `UseWorldCords` приходят нулями, но с `paramZero` — то есть
приложение само их не задало. Прежде чем чинить, надо понять, ожидает ли RA3 их через SAS-
привязку, которую мы не выполняем (`effects` показывает 266 параметров с `SasBindAddress`).

### 3. Две исходные задачи, не тронутые
- пустые выпадающие списки настроек/лобби; на экране статистики видны сырые ключи
  `APT:PostGamePlayerName0` вместо имён;
- внутриигровые ролики не проверялись.

## Как воспроизвести

```
bun tools/harness.ts up
BS_TAB=ra3 bun tools/probes/ra3v-cube-verify.harness.ts     # boot → скирмиш → метрики (~6 мин)
BS_TAB=ra3 bun tools/probes/ra3v-relevel.harness.ts         # со статистики обратно в бой
bun tools/shader-offline.ts logs/ra3/shader-blobs.json
```

## Грабли этой сессии (сэкономят время)

- **Проба пишет результат и потом висит** на CDP-сокете. `logs/ra3/*.json` уже готов, процесс
  живой — это норма. Перед новой пробой убивать старых клиентов, иначе вторая получает
  `Inspected target navigated or closed` и умирает на середине.
- **`bun tools/harness.ts <verb>`** работает надёжнее, чем DSL `.run()` из пробы, который у
  меня несколько раз уходил в таймаут.
- Вывод CLI начинается со строки журнала — JSON парсить с `tail -n +2`.
- **Статистика таргета врёт про содержимое.** `rtGallery` говорил «uniform 1.22», дамп
  показывал чёрное с красным клинышком. Смотреть пиксели.

## Гейт

typecheck зелёный; `tools/tests/d3d9*`, `d3dx9*`, `ffp-lighting` — 1204 теста зелёные.
Полный `bun run gate` **не прогонялся**. Новые тесты: `d3dx9-cube-dds`,
`d3d9-shader-bytecode-extent`, `d3d9-resource-edge` (+3), `ffp-lighting` (+3) — у каждого
проверено, что он падает на старом поведении.

Изменения не закоммичены и лежат вперемешку с чужой незакоммиченной работой в дереве —
